# M6 — macOS Backend (Swift/AppKit shell over C-ABI Zig core): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **SPLIT DECISION (read first).** M6 is the largest milestone since M2. It is split into two plans:
> - **M6a — `libnd` extraction + Linux-parity regression (THIS FILE, fully specified, 6 tasks).** Refactors the existing host into a reusable core library `libnd` fronted by a flat C ABI (`include/nd.h`), moving the backend seam *across* the C boundary so a non-Zig shell can supply widget operations as C callbacks. The GTK path is re-plumbed to sit on top of that same C ABI (a thin Zig `main` that registers the GTK backend as callbacks) and must stay **byte-identical** — same `nd-hello` binary, same markers, the whole existing Linux gate green. **Zero macOS code lands in M6a.** This is the M1-equivalent de-risk done as a pure refactor: prove the C ABI carries the full existing behaviour on Linux before a single line of Swift depends on it.
> - **M6b — Swift/AppKit shell + widget parity + TCC-free automation (OUTLINE at the end, ~7 tasks).** The SwiftPM shell that links `libnd`, the codegen Swift emitter (D6), the 18-widget AppKit backend, `NSView` in-process screenshots, semantic input, and the counter+gallery demos driven by MCP over `ssh macbook`. M6b is authored as its own full plan file (`2026-07-11-m6b-macos-shell.md`) once M6a is green.
>
> **Why split.** The C-ABI extraction touches every core file (`main.zig`, `runtime.zig`, `automation.zig`, `build.zig`) and its sole acceptance test is "Linux is byte-identical" — a self-contained, independently-verifiable unit that can (and must) land and stay green before any Mac work. Bundling the Swift shell into the same plan would make the regression gate depend on Mac hardware and blur the "did the refactor change Linux behaviour?" signal. Landing M6a first means M6b's every task has a stable, tested C ABI to build against.

## Goal (M6a)

Extract the existing host into a **core library `libnd`** with a **flat C ABI** (`include/nd.h`) such that:

1. The **backend seam crosses the C ABI.** Today `tree.zig` calls `backend.impl.<fn>` chosen at comptime (`gtk`|`null`). After M6a, the core exposes a **C-callback backend vtable**: the embedder (the GTK `main`, later the Swift shell) registers C function pointers for `create/applyProps/appendChild/insertBefore/removeChild/setText/setVisible/applyStyle/connectEvents/hasParent/unparentWidget` at init, and the core calls *up* through them (the Ghostty `ghostty_runtime_config_s` / `wakeup_cb`/`action_cb` pattern). The comptime `gtk`|`null` seam is **retained for the null-backend conformance target** (in-process, no C round-trip) — M6a adds a **third path: a C-vtable backend** used by real embedders.
2. The **entire existing host (runtime, tree, protocol, automation, style, overlay) becomes `libnd`** minus the GTK-specific widget code. `libnd` is a static library (`libnd.a`) with `include/nd.h` as its only public surface: `nd_init`, `nd_register_backend`, `nd_run` / event-loop integration, plus the automation query entrypoints. The GTK backend (`gtk_backend.zig` + `generated/widgets.zig`) becomes the **first C-ABI embedder**, unchanged in behaviour.
3. **Linux stays byte-identical.** `build.zig` produces **both** the `nd-hello` executable (Linux, GTK embedder over the C ABI) **and** `libnd.a` (for the Mac, built natively there in M6b) from shared modules. The full existing Linux gate stays green after every task; `nd-hello`'s markers, socket behaviour, HMR, overlay, and automation are unchanged.

**No schema changes** except (if genuinely needed) additive automation metadata — none is anticipated in M6a. No new widget scope. No React/TS changes.

**Non-goals (M6a):** any Swift code, any AppKit widget, the codegen Swift emitter, the Mac scripts. All of that is M6b.

### Zig 0.16 drift facts that bite this milestone (from CLAUDE-activeContext, all verified in-repo)

- **`std.Io` sockets / mutex / spawn drift** (already handled in `runtime.zig`/`automation.zig`): `std.Io.net`, `std.Io.Mutex = .init` (needs the default init — `self.* = undefined` skips field defaults and bricks it), `std.process.spawn(io, .{.environ_map=…})`, `std.Io.sleep(io, .fromMilliseconds(n), .awake)`. The C ABI must thread `std.Io` through init exactly as `Runtime.start`/`automation.Server.start` do — do not re-create it per call.
- **`gio.Application.run` parses argv itself** — the GTK embedder passes `argc=0/argv=null` after parsing host flags. This lives in the GTK `main`, which stays on the Linux side of the ABI.
- **Zig 0.16 does NOT collect tests transitively through `@import`** — every test-bearing file needs its own `addTest` root in `build.zig` (bit `style.zig` this session). Any file M6a moves/renames must keep or gain its own test root.
- **`callconv(.c)` + `export`** is how Zig emits C-ABI symbols; the C header types must match Zig's `extern struct` / `[*:0]const u8` / `?*anyopaque` layouts exactly. No `@cImport` — the header is hand-written and kept in lockstep by a compile-time layout assertion (Task 1).

## M6a decision record (owner-facing judgment calls, locked by this plan)

- **M6a-D1 — The C ABI is a *backend vtable* registered at init; the core owns the loop and calls up.** `include/nd.h` defines `NdBackend` (an `extern struct` of C function pointers, one per seam operation) plus lifecycle (`nd_init`, `nd_register_backend`, `nd_start_runtime`, `nd_start_automation`) and event/loop integration. The embedder (GTK `main`, later Swift `main`) creates its native app + event loop, fills an `NdBackend`, calls `nd_init`/`nd_register_backend`, and drives its loop; the core's `tree.apply` calls the vtable's `create`/`append`/… on the embedder's loop thread (the embedder marshals to its UI thread — GLib `invokeFull` today, `dispatch_async_f` on Mac). This is the Ghostty `ghostty_runtime_config_s` pattern (research [1]) — Swift registers callbacks, the Zig core invokes them. **Chosen over "core owns the widgets, backend is pure Zig comptime"** because D7 mandates the widget layer live in Swift (SwiftUI reachability, Apple-supported path), which is only possible if the backend surface crosses a C boundary the Swift shell implements.
- **M6a-D2 — Props and text cross the ABI as NUL-terminated UTF-8 JSON strings; widgets/events cross as opaque `void*` + primitive scalars.** The core already holds each op's `props` as a `std.json.Value` slice of the commit frame; for a vtable call it re-stringifies that one op's props (`std.json.Stringify.valueAlloc`, freed after the call) and passes `[*:0]const u8`. The GTK embedder re-parses with the same `std.json` — so the round-trip is lossless and Linux behaviour is semantically identical (the extra stringify/parse is per-op, negligible, and only on the create/update path). **Chosen over a binary/typed C struct per widget** because (a) it is language-neutral (Swift re-parses with `JSONSerialization` in M6b, or a codegen'd decoder), (b) it keeps the ABI tiny and stable across schema growth (new props need no ABI change — the D6 win), and (c) it mirrors how the wire protocol already moves props. Event payloads flow *up* the same way (core→embedder is native; embedder→core events call `nd_emit_event(node_id, name, payload_json)`).
- **M6a-D3 — Automation splits into a portable core half and a backend-specific half; the backend-specific half joins the vtable.** `getTree` is *mostly* portable — it walks `Tree.meta`/`Tree.nodes` (host bookkeeping) and needs only two backend facts per node: **is-visible** and **geometry (bounds in window space)**. `screenshot`, `click`, `setValue`, `type`, `scroll` are **entirely backend-specific** (GTK signal emit / GtkEditable / adjustments today; NSView/NSControl on Mac). **Decision:** the automation *server* (socket, JSON-RPC framing, `waitFor` polling, envelope building, the SIGSTOP-survivability — all of `automation.zig`'s `Server`/`dispatch`/`runOnUi` machinery) stays in the **core** and answers while the Bun child is stalled (the D11 SLO is a core property — the automation thread + UI marshal are core-owned). The **per-operation implementations** (`handleScreenshot`, `handleClick`, `handleSetValue`, `handleType`, `handleScroll`, plus per-node `isVisible`/`computeBounds` for `getTree`) become **vtable callbacks** the backend supplies: `nd_backend.snapshot(path)`, `nd_backend.semantic_action(node_id, action, arg_json)`, `nd_backend.node_visible(widget)`, `nd_backend.node_bounds(widget, out_rect)`. The GTK backend fills them with today's exact code (byte-identical); the Swift backend fills them with AppKit in M6b. **This keeps the SLO test (automation answers under child SIGSTOP) a core guarantee on every platform** — the automation thread never crosses into JS, only into the (fast, main-thread-marshaled) backend vtable. `getTree`'s node/child *walk* stays in the core; only the two per-node backend facts are vtable calls.
  - **M6a scope note:** M6a implements the vtable *shape* and routes the **GTK** backend's automation through it (proving the split on Linux, gate stays green). It does **not** implement any Mac automation — that is M6b. So after M6a, `automation.zig`'s GTK-specific handlers have moved behind `nd_backend.*` callbacks *filled by the GTK embedder*, and the SLO/getTree/screenshot Linux scripts still pass.
- **M6a-D4 — `build.zig` produces both `nd-hello` (exe, GTK-over-ABI) and `libnd.a` (static lib) from one shared `core` module.** A new `core` Zig module (root `src/core/root.zig`, re-exporting `runtime`+`tree`+`protocol`+`automation`+`style`+`overlay`+the `abi` exports) is compiled once. The **Linux exe** = `core` + the GTK embedder (`src/gtk/main.zig` + `gtk_backend.zig` + `generated/widgets.zig`) linked against gobject bindings, selected by `-Dbackend=gtk` (default). The **static lib** `libnd.a` = `core` with `-Dbackend=abi` and **no GTK imports at all** (it must build on the Mac where GTK is absent) — its backend is the C vtable. `zig build libnd` emits `libnd.a` + copies `include/nd.h`. **Chosen over two separate builds** because sharing the `core` module is what guarantees the Mac and Linux run the *same* runtime/tree/automation/protocol code — the D7/D1 whole point.
  - **The `abi` backend module must not import `gtk`.** This is enforced structurally: `src/abi_backend.zig` imports only `std` + `protocol` + the C vtable; `build.zig`'s `libnd` artifact does not add the gobject imports. If any core file (`runtime`/`automation`/`tree`) still imports `gtk` directly, `libnd` fails to compile on the Mac — that compile failure *is* the test that the extraction is complete (Task 3/4 drive those imports to zero).
- **M6a-D5 — The comptime `null` seam and the runtime `abi` seam coexist.** Conformance keeps using `-Dbackend=null` (in-process `null_backend.zig`, no C round-trip — fast, display-free, unchanged). Real embedders use `-Dbackend=abi`. `-Dbackend=gtk` remains as a **direct** (non-ABI) path ONLY if we choose to keep a zero-indirection Linux build; **decision: retire the direct `gtk` seam and route Linux through `abi` too**, so the C ABI is exercised by the *entire Linux gate* on every CI run (maximal de-risk for the Mac). The `gtk_backend`'s functions become the GTK embedder's vtable fills. `null` stays comptime (conformance must not need a C embedder). So post-M6a: `-Dbackend` ∈ {`null` (comptime, conformance), `abi` (C vtable, all real embedders)}; the string `gtk` is gone from `backend.zig` (the GTK-ness now lives in the *embedder*, not the seam).

   lockstep with src/abi.zig by compile-time @sizeOf asserts. */
#ifndef ND_H
#define ND_H
#include <stdint.h>
#include <stdbool.h>

typedef void* nd_widget;              /* opaque backend handle (GtkWidget* / NSView*) */
typedef struct nd_context nd_context; /* opaque core instance */

/* Geometry in logical window-top-left space (matches getTree contract). */
typedef struct { int32_t x, y, w, h; } nd_rect;

/* The backend vtable: the embedder fills these; the core calls up through them.
   `props_json` / `arg_json` are NUL-terminated UTF-8 JSON (M6a-D2). All calls
   arrive on the embedder's UI thread (the core marshals). */
typedef struct nd_backend {
  /* structural + prop ops (mirror the Zig seam) */
  nd_widget (*create)(nd_context*, const char* kind, const char* props_json);
  void (*apply_props)(nd_context*, nd_widget, const char* kind, const char* props_json);
  void (*append_child)(nd_context*, nd_widget parent, const char* parent_kind,
                       nd_widget child, const char* attached_json);
  void (*insert_before)(nd_context*, nd_widget parent, const char* parent_kind,
                        nd_widget child, nd_widget before /* nullable */,
                        const char* attached_json);
  void (*remove_child)(nd_context*, nd_widget parent, const char* parent_kind, nd_widget child);
  void (*set_text)(nd_context*, nd_widget, const char* text);
  void (*set_visible)(nd_context*, nd_widget, bool visible);
  void (*apply_style)(nd_context*, nd_widget, uint32_t node_id, const char* style_json);
  void (*connect_events)(nd_context*, nd_widget, const char* kind, uint32_t node_id);
  bool (*has_parent)(nd_context*, nd_widget);
  void (*unparent)(nd_context*, nd_widget);
  nd_widget (*get_window)(nd_context*);

  /* automation backend half (M6a-D3) */
  bool (*node_visible)(nd_context*, nd_widget);
  bool (*node_bounds)(nd_context*, nd_widget, nd_rect* out);   /* false = no bounds */
  bool (*snapshot)(nd_context*, const char* png_path);         /* in-process render */
  /* action: "click"|"setValue"|"type"|"scroll"; arg_json carries params.
     returns 0 ok, or a negative JSON-RPC-style code; err_json_out (nullable,
     caller frees via nd_free) gets a data object on failure. */

                             const char* action, const char* arg_json,
                             char** result_json_out, char** err_json_out);
} nd_backend;

/* lifecycle */
nd_context* nd_init(void);                                  /* create core, spawn nothing yet */
void nd_register_backend(nd_context*, const nd_backend*);   /* store the vtable */
int32_t nd_start_runtime(nd_context*);                      /* open NDP socket, spawn bun child */
int32_t nd_start_automation(nd_context*);                   /* open automation socket + thread */
void nd_free(void* p);                                      /* free a core-allocated string */

/* embedder -> core: a native event happened (button clicked, text changed, …).
   `payload_json` is a NUL-terminated JSON object or "{}". */
void nd_emit_event(nd_context*, uint32_t node_id, const char* name, const char* payload_json);

## Parallelism note (M6a)

M6a is a **strict spine** — Tasks 1→2→3→4→5→6 each build on the prior task's ABI shape. # M6b — Swift/AppKit shell + widget parity + TCC-free automation (OUTLINE)
